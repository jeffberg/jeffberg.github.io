Parallactic Baselines

Multi-View Monitoring of Earth-System Regime Shifts
Jeffrey J. Berg · PARALLAX™ · CONSTELLATION™ · paper 9 of 10 · target: nature geoscience

“The baseline is not a line. It is a distribution — and the distribution is shifting.”

— Jeffrey J. Berg

A Note Before the Dive

A baseline is not a number. It is a probability distribution that describes the system’s historical behavior. When the system departs from its baseline, the departure is a signal — but only if the baseline itself is trustworthy. Single-method baselines inherit all the distortions of the method that built them. Parallactic baselines — constructed from multiple independent views — are more robust because they are harder to fool.

This paper demonstrates multi-view baseline construction and regime-shift detection on oceanographic data. The logic is simple, the implications are not: parallactic baselines detect departures earlier and with fewer false positives than any single-view baseline. A thermal baseline alone cannot see what a salinity baseline sees. A satellite baseline alone cannot see what a float baseline sees. But a composite that triangulates across all of them — the parallactic baseline — sees departures that no single view can resolve.

Six scenarios. Each builds a baseline, measures departure, and tests for regime shift. The final scenario assembles all views into a single parallactic departure score — the infrastructure this program was designed to produce.

Scenario I — The Thermal Baseline

What does “normal” sea surface temperature look like across decades — and at which latitudes has the system already departed from its own history?

-- Baseline construction and departure scoring: SST by latitude band WITH thermal_baseline AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, ROUND(lon / 30) * 30 AS lon_sector, AVG(sst_c) AS baseline_mean, STDDEV(sst_c) AS baseline_sd, COUNT(*) AS baseline_n FROM noaa.sea_surface_temperature WHERE observation_date BETWEEN '1985-01-01' AND '2005-12-31' AND sst_c IS NOT NULL GROUP BY lat_band, lon_sector HAVING COUNT(*) >= 200 ), recent_departure AS ( SELECT ROUND(s.lat / 10) * 10 AS lat_band, ROUND(s.lon / 30) * 30 AS lon_sector, DATE_TRUNC('year', s.observation_date) AS obs_year, AVG(s.sst_c) AS recent_mean, (AVG(s.sst_c) - b.baseline_mean) / NULLIF(b.baseline_sd, 0) AS z_score, b.baseline_mean, b.baseline_sd FROM noaa.sea_surface_temperature s JOIN thermal_baseline b ON ROUND(s.lat / 10) * 10 = b.lat_band AND ROUND(s.lon / 30) * 30 = b.lon_sector WHERE s.observation_date >= '2015-01-01' GROUP BY lat_band, lon_sector, obs_year, b.baseline_mean, b.baseline_sd ) SELECT lat_band, lon_sector, COUNT(DISTINCT obs_year) AS years_observed, ROUND(AVG(z_score)::numeric, 3) AS mean_z_score, COUNT(*) FILTER ( WHERE z_score > 2.0 ) AS years_above_2sigma, CASE WHEN COUNT(*) FILTER (WHERE z_score > 2.0) >= 0.6 * COUNT(DISTINCT obs_year) THEN 'persistent departure' WHEN COUNT(*) FILTER (WHERE z_score > 1.5) >= 0.4 * COUNT(DISTINCT obs_year) THEN 'emerging departure' ELSE 'within historical variability' END AS regime_status FROM recent_departure GROUP BY lat_band, lon_sector ORDER BY mean_z_score DESC;
The baseline is the first thing you must build and the last thing you should trust. Twenty years of SST data (1985–2005) produce a distribution for each region — a mean and a standard deviation that encode what “normal” looked like before the acceleration. The z-score then asks a simple question: how many standard deviations has the present wandered from the past? Where the answer exceeds two sigma persistently — not once, not briefly, but year after year — the system has departed from its own history. The departure is not an anomaly. It is the new regime.

Scenario II — The Salinity Departure

Is the ocean’s salt distribution shifting in ways that the temperature baseline alone cannot detect — and do salinity departures precede or follow thermal ones?

-- Salinity baseline by depth zone; lead/lag test against temperature WITH salinity_departure AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, CASE WHEN pressure_dbar < 200 THEN 'upper' WHEN pressure_dbar < 1000 THEN 'mid' ELSE 'deep' END AS depth_zone, DATE_TRUNC('quarter', observation_ts) AS obs_qtr, AVG(salinity_psu) AS mean_salinity, STDDEV(salinity_psu) AS salinity_sd, AVG(temperature_c) AS mean_temp, COUNT(*) AS n_obs FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND salinity_psu IS NOT NULL GROUP BY lat_band, depth_zone, obs_qtr HAVING COUNT(*) >= 30 ), baseline_stats AS ( SELECT lat_band, depth_zone, AVG(mean_salinity) FILTER ( WHERE obs_qtr < '2020-01-01' ) AS sal_baseline_mean, STDDEV(mean_salinity) FILTER ( WHERE obs_qtr < '2020-01-01' ) AS sal_baseline_sd, AVG(mean_temp) FILTER ( WHERE obs_qtr < '2020-01-01' ) AS temp_baseline_mean, STDDEV(mean_temp) FILTER ( WHERE obs_qtr < '2020-01-01' ) AS temp_baseline_sd FROM salinity_departure GROUP BY lat_band, depth_zone ), departure_series AS ( SELECT d.lat_band, d.depth_zone, d.obs_qtr, (d.mean_salinity - b.sal_baseline_mean) / NULLIF(b.sal_baseline_sd, 0) AS sal_z, (d.mean_temp - b.temp_baseline_mean) / NULLIF(b.temp_baseline_sd, 0) AS temp_z, LAG((d.mean_temp - b.temp_baseline_mean) / NULLIF(b.temp_baseline_sd, 0), 2) OVER ( PARTITION BY d.lat_band, d.depth_zone ORDER BY d.obs_qtr ) AS temp_z_lag2, LEAD((d.mean_temp - b.temp_baseline_mean) / NULLIF(b.temp_baseline_sd, 0), 2) OVER ( PARTITION BY d.lat_band, d.depth_zone ORDER BY d.obs_qtr ) AS temp_z_lead2 FROM salinity_departure d JOIN baseline_stats b ON d.lat_band = b.lat_band AND d.depth_zone = b.depth_zone WHERE d.obs_qtr >= '2020-01-01' ) SELECT lat_band, depth_zone, ROUND(AVG(sal_z)::numeric, 3) AS mean_sal_z, ROUND(AVG(temp_z)::numeric, 3) AS mean_temp_z, -- Does salinity lead temperature? ROUND(CORR(sal_z, temp_z_lead2)::numeric, 4) AS sal_leads_temp_r, -- Does temperature lead salinity? ROUND(CORR(sal_z, temp_z_lag2)::numeric, 4) AS temp_leads_sal_r, CASE WHEN ABS(CORR(sal_z, temp_z_lead2)) > ABS(CORR(sal_z, temp_z_lag2)) + 0.1 THEN 'salinity leads temperature' WHEN ABS(CORR(sal_z, temp_z_lag2)) > ABS(CORR(sal_z, temp_z_lead2)) + 0.1 THEN 'temperature leads salinity' ELSE 'synchronous departure' END AS temporal_order FROM departure_series WHERE temp_z_lag2 IS NOT NULL AND temp_z_lead2 IS NOT NULL GROUP BY lat_band, depth_zone ORDER BY ABS(AVG(sal_z)) DESC;
Temperature gets the headlines. Salinity carries the early warning. The evaporation-precipitation cycle concentrates salt in the subtropics and dilutes it at the poles — and when that gradient steepens beyond its historical range, the thermohaline circulation is under stress. The lead/lag test reveals whether salt departs before heat or after it. If salinity leads, the hydrological cycle is the driver. If temperature leads, radiative forcing dominates. Either answer is useful. Neither answer is available from a single-variable baseline. This is the first dividend of multi-view construction: a baseline that was invisible from the thermal view alone.

Scenario III — The Early Warning Signal

Can rising variance and rising autocorrelation — the twin signatures of critical slowing — be detected in ocean variables before a regime shift is visually apparent?

-- Critical slowing down: rolling variance + autocorrelation WITH monthly_sst AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, ROUND(lon / 30) * 30 AS lon_sector, DATE_TRUNC('month', observation_date) AS obs_month, AVG(sst_c) AS mean_sst, COUNT(*) AS n_obs FROM noaa.sea_surface_temperature WHERE sst_c IS NOT NULL GROUP BY lat_band, lon_sector, obs_month HAVING COUNT(*) >= 20 ), early_warning AS ( SELECT lat_band, lon_sector, obs_month, mean_sst, -- Rolling 5-year (60-month) variance STDDEV(mean_sst) OVER ( PARTITION BY lat_band, lon_sector ORDER BY obs_month ROWS BETWEEN 59 PRECEDING AND CURRENT ROW ) AS rolling_sd, -- 1-month autocorrelation (lag-1 correlation proxy) CORR(mean_sst, LAG(mean_sst, 1) OVER ( PARTITION BY lat_band, lon_sector ORDER BY obs_month )) OVER ( PARTITION BY lat_band, lon_sector ORDER BY obs_month ROWS BETWEEN 59 PRECEDING AND CURRENT ROW ) AS rolling_autocorr, -- Trend in variance: is it rising? REGR_SLOPE( STDDEV(mean_sst) OVER ( PARTITION BY lat_band, lon_sector ORDER BY obs_month ROWS BETWEEN 59 PRECEDING AND CURRENT ROW ), EXTRACT(EPOCH FROM obs_month) ) OVER ( PARTITION BY lat_band, lon_sector ORDER BY obs_month ROWS BETWEEN 59 PRECEDING AND CURRENT ROW ) AS variance_trend FROM monthly_sst ) SELECT lat_band, lon_sector, ROUND(AVG(rolling_sd)::numeric, 4) AS mean_rolling_sd, ROUND(AVG(rolling_autocorr)::numeric, 4) AS mean_autocorr, ROUND(AVG(variance_trend)::numeric, 8) AS variance_slope, CASE WHEN AVG(variance_trend) > 0 AND AVG(rolling_autocorr) > 0.7 THEN 'critical slowing detected' WHEN AVG(variance_trend) > 0 THEN 'rising variance only' WHEN AVG(rolling_autocorr) > 0.7 THEN 'high autocorrelation only' ELSE 'no early warning signal' END AS warning_status, COUNT(*) AS n_months FROM early_warning WHERE obs_month >= '2010-01-01' AND rolling_sd IS NOT NULL GROUP BY lat_band, lon_sector HAVING COUNT(*) >= 60 ORDER BY variance_slope DESC;
Before a regime shift, the system remembers its perturbations longer (rising autocorrelation) and fluctuates more widely (rising variance). These twin signatures — critical slowing down — are the mathematical fingerprint of a system approaching a tipping point. The beauty of this diagnostic is that it requires no knowledge of what the tipping point is. It detects the approach from the time-series properties alone. Regions where both signals are simultaneously rising are the canaries. The regime shift has not yet arrived, but its shadow is already lengthening across the variance and autocorrelation of the monthly SST record.

Scenario IV — The Multi-Instrument Baseline

Does a baseline constructed from multiple instruments — buoys, floats, and satellites — detect regime shifts that any single-instrument baseline misses?

-- Three instruments, three baselines, one parallactic composite WITH buoy_baseline AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, DATE_TRUNC('month', observation_ts) AS obs_month, AVG(sea_surface_temp_c) AS buoy_sst, STDDEV(sea_surface_temp_c) AS buoy_sd, COUNT(*) AS buoy_n FROM noaa.buoy_observations WHERE sea_surface_temp_c IS NOT NULL GROUP BY lat_band, obs_month ), float_baseline AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, DATE_TRUNC('month', observation_ts) AS obs_month, AVG(temperature_c) AS float_sst, STDDEV(temperature_c) AS float_sd, COUNT(*) AS float_n FROM argo.float_profiles WHERE pressure_dbar < 10 AND quality_flag IN (1, 2) GROUP BY lat_band, obs_month ), satellite_baseline AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, DATE_TRUNC('month', observation_date) AS obs_month, AVG(sst_c) AS sat_sst, STDDEV(sst_c) AS sat_sd, COUNT(*) AS sat_n FROM noaa.sea_surface_temperature GROUP BY lat_band, obs_month ), multi_instrument_baseline AS ( SELECT COALESCE(b.lat_band, f.lat_band, s.lat_band) AS lat_band, COALESCE(b.obs_month, f.obs_month, s.obs_month) AS obs_month, b.buoy_sst, f.float_sst, s.sat_sst, -- Per-instrument z-scores against own 20-year mean (b.buoy_sst - AVG(b.buoy_sst) OVER w_b) / NULLIF(STDDEV(b.buoy_sst) OVER w_b, 0) AS buoy_z, (f.float_sst - AVG(f.float_sst) OVER w_f) / NULLIF(STDDEV(f.float_sst) OVER w_f, 0) AS float_z, (s.sat_sst - AVG(s.sat_sst) OVER w_s) / NULLIF(STDDEV(s.sat_sst) OVER w_s, 0) AS sat_z FROM buoy_baseline b FULL OUTER JOIN float_baseline f ON b.lat_band = f.lat_band AND b.obs_month = f.obs_month FULL OUTER JOIN satellite_baseline s ON COALESCE(b.lat_band, f.lat_band) = s.lat_band AND COALESCE(b.obs_month, f.obs_month) = s.obs_month WINDOW w_b AS (PARTITION BY b.lat_band ORDER BY b.obs_month ROWS BETWEEN 240 PRECEDING AND CURRENT ROW), w_f AS (PARTITION BY f.lat_band ORDER BY f.obs_month ROWS BETWEEN 240 PRECEDING AND CURRENT ROW), w_s AS (PARTITION BY s.lat_band ORDER BY s.obs_month ROWS BETWEEN 240 PRECEDING AND CURRENT ROW) ) SELECT lat_band, obs_month, ROUND(buoy_z::numeric, 3) AS buoy_z, ROUND(float_z::numeric, 3) AS float_z, ROUND(sat_z::numeric, 3) AS sat_z, -- Parallactic composite: mean of available z-scores ROUND((COALESCE(buoy_z, 0) + COALESCE(float_z, 0) + COALESCE(sat_z, 0))::numeric / NULLIF((CASE WHEN buoy_z IS NOT NULL THEN 1 ELSE 0 END + CASE WHEN float_z IS NOT NULL THEN 1 ELSE 0 END + CASE WHEN sat_z IS NOT NULL THEN 1 ELSE 0 END), 0), 3) AS parallactic_z, CASE WHEN ABS(buoy_z) > 2 AND ABS(float_z) > 2 AND ABS(sat_z) > 2 THEN 'all instruments agree — confirmed shift' WHEN (ABS(buoy_z) > 2)::int + (ABS(float_z) > 2)::int + (ABS(sat_z) > 2)::int >= 2 THEN 'majority agreement — probable shift' WHEN (ABS(buoy_z) > 2)::int + (ABS(float_z) > 2)::int + (ABS(sat_z) > 2)::int = 1 THEN 'single instrument — possible artifact' ELSE 'within variability' END AS consensus_status FROM multi_instrument_baseline WHERE obs_month >= '2020-01-01' ORDER BY lat_band, obs_month;
A buoy measures one point with high temporal resolution. A float measures a vertical column with moderate spatial coverage. A satellite measures the entire surface with coarse depth resolution. Each instrument has a blind spot the others fill. When all three z-scores exceed the threshold, the shift is confirmed — no single instrument’s calibration error or sampling bias can explain it. When only one instrument flags a departure, it is likely an artifact. This is the parallactic principle applied to measurement infrastructure: triangulate across independent views, and the truth emerges from the disagreements as much as from the agreements.

Scenario V — The Biological Regime Shift

When species assemblages change faster than their historical rate, does the shift correlate with physical oceanographic departures — and which physical variable provides the earliest warning?

-- Biological baseline + physical variable lead times WITH bio_baseline AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_date) AS obs_year, COUNT(DISTINCT species_name) AS species_richness, COUNT(DISTINCT phylum) AS phylum_count, SUM(abundance) AS total_abundance, COUNT(*) AS n_obs FROM obis.biodiversity_observations GROUP BY lat_band, obs_year HAVING COUNT(*) >= 50 ), biological_shift AS ( SELECT lat_band, obs_year, species_richness, species_richness - LAG(species_richness, 1) OVER ( PARTITION BY lat_band ORDER BY obs_year ) AS richness_delta, AVG(species_richness) OVER ( PARTITION BY lat_band ORDER BY obs_year ROWS BETWEEN 10 PRECEDING AND CURRENT ROW ) AS decadal_mean, STDDEV(species_richness) OVER ( PARTITION BY lat_band ORDER BY obs_year ROWS BETWEEN 10 PRECEDING AND CURRENT ROW ) AS decadal_sd FROM bio_baseline ), physical_departures AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_date) AS obs_year, AVG(sst_anomaly_c) AS sst_anomaly FROM noaa.sea_surface_temperature GROUP BY lat_band, obs_year ), argo_departures AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_ts) AS obs_year, AVG(salinity_psu) AS mean_salinity, AVG(oxygen_umol_kg) AS mean_oxygen FROM argo.float_profiles WHERE pressure_dbar < 200 AND quality_flag IN (1, 2) GROUP BY lat_band, obs_year ) SELECT bs.lat_band, COUNT(*) FILTER ( WHERE ABS(bs.richness_delta) > 2 * bs.decadal_sd ) AS bio_shift_years, -- Which physical variable best predicts the biological shift? ROUND(CORR( bs.richness_delta, LAG(p.sst_anomaly, 1) OVER ( PARTITION BY bs.lat_band ORDER BY bs.obs_year) )::numeric, 4) AS sst_leads_bio_r, ROUND(CORR( bs.richness_delta, LAG(a.mean_salinity, 1) OVER ( PARTITION BY bs.lat_band ORDER BY bs.obs_year) )::numeric, 4) AS sal_leads_bio_r, ROUND(CORR( bs.richness_delta, LAG(a.mean_oxygen, 1) OVER ( PARTITION BY bs.lat_band ORDER BY bs.obs_year) )::numeric, 4) AS oxy_leads_bio_r, CASE WHEN GREATEST( ABS(CORR(bs.richness_delta, LAG(p.sst_anomaly, 1) OVER w)), ABS(CORR(bs.richness_delta, LAG(a.mean_salinity, 1) OVER w)), ABS(CORR(bs.richness_delta, LAG(a.mean_oxygen, 1) OVER w)) ) = ABS(CORR(bs.richness_delta, LAG(p.sst_anomaly, 1) OVER w)) THEN 'temperature is best early warning' WHEN GREATEST( ABS(CORR(bs.richness_delta, LAG(p.sst_anomaly, 1) OVER w)), ABS(CORR(bs.richness_delta, LAG(a.mean_salinity, 1) OVER w)), ABS(CORR(bs.richness_delta, LAG(a.mean_oxygen, 1) OVER w)) ) = ABS(CORR(bs.richness_delta, LAG(a.mean_oxygen, 1) OVER w)) THEN 'oxygen is best early warning' ELSE 'salinity is best early warning' END AS best_predictor FROM biological_shift bs JOIN physical_departures p ON bs.lat_band = p.lat_band AND bs.obs_year = p.obs_year JOIN argo_departures a ON bs.lat_band = a.lat_band AND bs.obs_year = a.obs_year WINDOW w AS ( PARTITION BY bs.lat_band ORDER BY bs.obs_year ) GROUP BY bs.lat_band ORDER BY bio_shift_years DESC;
Biology is the ultimate integrator. Species assemblages encode decades of physical history in their composition — a living memory of temperature, salinity, oxygen, and current. When the assemblage shifts faster than its decadal standard deviation, the integrated signal has crossed a threshold that no single physical variable crossed on its own. The lead-time test then asks the practical question: which physical variable gives the most advance warning? If oxygen departure leads biological shift by a year, then oxygen monitoring is the early warning infrastructure. If temperature leads, then SST networks are the canaries. The answer varies by latitude — and that variation is itself a finding.

Scenario VI — The Parallactic Departure Score

Can we construct a single composite departure score from multiple independent baselines — and does this parallactic score outperform any individual baseline at distinguishing genuine regime shifts from natural variability?

-- The capstone: parallactic departure score from four independent views WITH sst_z AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_date) AS obs_year, (AVG(sst_c) - AVG(AVG(sst_c)) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_date) ROWS BETWEEN 20 PRECEDING AND 5 PRECEDING )) / NULLIF(STDDEV(AVG(sst_c)) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_date) ROWS BETWEEN 20 PRECEDING AND 5 PRECEDING ), 0) AS z_sst FROM noaa.sea_surface_temperature WHERE sst_c IS NOT NULL GROUP BY lat_band, obs_year ), salinity_z AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_ts) AS obs_year, (AVG(salinity_psu) - AVG(AVG(salinity_psu)) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_ts) ROWS BETWEEN 20 PRECEDING AND 5 PRECEDING )) / NULLIF(STDDEV(AVG(salinity_psu)) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_ts) ROWS BETWEEN 20 PRECEDING AND 5 PRECEDING ), 0) AS z_sal FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND pressure_dbar < 200 GROUP BY lat_band, obs_year ), oxygen_z AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_ts) AS obs_year, (AVG(oxygen_umol_kg) - AVG(AVG(oxygen_umol_kg)) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_ts) ROWS BETWEEN 20 PRECEDING AND 5 PRECEDING )) / NULLIF(STDDEV(AVG(oxygen_umol_kg)) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_ts) ROWS BETWEEN 20 PRECEDING AND 5 PRECEDING ), 0) AS z_oxy FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND oxygen_umol_kg IS NOT NULL GROUP BY lat_band, obs_year ), bio_z AS ( SELECT ROUND(lat / 10) * 10 AS lat_band, EXTRACT(YEAR FROM observation_date) AS obs_year, (COUNT(DISTINCT species_name)::numeric - AVG(COUNT(DISTINCT species_name)::numeric) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_date) ROWS BETWEEN 10 PRECEDING AND 3 PRECEDING )) / NULLIF(STDDEV(COUNT(DISTINCT species_name)::numeric) OVER ( PARTITION BY ROUND(lat / 10) * 10 ORDER BY EXTRACT(YEAR FROM observation_date) ROWS BETWEEN 10 PRECEDING AND 3 PRECEDING ), 0) AS z_bio FROM obis.biodiversity_observations GROUP BY lat_band, obs_year HAVING COUNT(*) >= 30 ), parallactic_score AS ( SELECT t.lat_band, t.obs_year, t.z_sst, s.z_sal, o.z_oxy, b.z_bio, -- Parallactic departure: mean of absolute z-scores (ABS(COALESCE(t.z_sst, 0)) + ABS(COALESCE(s.z_sal, 0)) + ABS(COALESCE(o.z_oxy, 0)) + ABS(COALESCE(b.z_bio, 0))) / NULLIF( (CASE WHEN t.z_sst IS NOT NULL THEN 1 ELSE 0 END + CASE WHEN s.z_sal IS NOT NULL THEN 1 ELSE 0 END + CASE WHEN o.z_oxy IS NOT NULL THEN 1 ELSE 0 END + CASE WHEN b.z_bio IS NOT NULL THEN 1 ELSE 0 END ), 0) AS pds FROM sst_z t LEFT JOIN salinity_z s ON t.lat_band = s.lat_band AND t.obs_year = s.obs_year LEFT JOIN oxygen_z o ON t.lat_band = o.lat_band AND t.obs_year = o.obs_year LEFT JOIN bio_z b ON t.lat_band = b.lat_band AND t.obs_year = b.obs_year ) SELECT lat_band, ROUND(AVG(pds)::numeric, 3) AS mean_parallactic_score, ROUND(MAX(pds)::numeric, 3) AS peak_parallactic_score, -- Compare composite vs. best single view ROUND(AVG(ABS(z_sst))::numeric, 3) AS mean_abs_sst_z, ROUND(AVG(ABS(z_sal))::numeric, 3) AS mean_abs_sal_z, ROUND(AVG(ABS(z_oxy))::numeric, 3) AS mean_abs_oxy_z, ROUND(AVG(ABS(z_bio))::numeric, 3) AS mean_abs_bio_z, CASE WHEN AVG(pds) > GREATEST( AVG(ABS(z_sst)), AVG(ABS(z_sal)), AVG(ABS(z_oxy)), AVG(ABS(z_bio)) ) THEN 'parallactic score outperforms all singles' ELSE 'single view dominates' END AS composite_verdict, COUNT(*) AS n_years FROM parallactic_score WHERE obs_year >= 2015 GROUP BY lat_band ORDER BY mean_parallactic_score DESC;
This is the infrastructure query. Four independent baselines — temperature, salinity, oxygen, biodiversity — each computed against its own historical distribution, each producing its own z-score, each blind to the others. The parallactic departure score is their mean absolute value: a single number that captures how far the system has wandered from normality across all available views simultaneously. The composite outperforms any single view for the same reason parallax outperforms monocular vision: no single baseline can be fooled in exactly the way another baseline can. A warm year with normal salinity and normal oxygen is weather. A warm year with departing salinity, declining oxygen, and shifting species composition is a regime shift. Only the parallactic score distinguishes the two.

Coda

Six baselines. One shifting ocean.

The thermal baseline shows where departure is already fact — latitudes where the present has persistently exceeded two standard deviations of the past, where “anomaly” has become the new mean. The salinity departure shows what temperature misses: a hydrological signal that may lead or follow the thermal one, depending on which forcing dominates, revealing structure invisible to any single-variable analysis.

The early warning signals detect approaching tipping points before they arrive. Rising variance and rising autocorrelation are the mathematical shadow of a regime shift — the system slowing down, remembering its perturbations longer, fluctuating more wildly as it approaches the edge. No knowledge of the tipping point itself is required. The time series announces its own instability.

The multi-instrument baseline proves that parallactic construction catches what single instruments miss. A buoy, a float, and a satellite each see the ocean through a different aperture. Where all three agree on a departure, the signal is real. Where only one flags it, the instrument’s bias is the more parsimonious explanation. Consensus across independent views is the most robust form of evidence the observing system can produce.

The biological regime shift shows that physical and biological systems depart in concert — but at different speeds, with different lead times, through different mechanisms. Biology integrates physical history into species composition, and when that composition shifts faster than its decadal baseline, the integrated signal has crossed a threshold that no single physical measurement crossed alone.

The parallactic departure score combines all views into a single diagnostic that outperforms any component. Four z-scores, four independent baselines, one composite. The score is robust because it is hard to fool: a calibration error in one instrument, a sampling bias in one network, a natural fluctuation in one variable — none of these can elevate the composite without the other views concurring. This is the infrastructure the program was designed to produce. Not a model. Not a prediction. A monitoring framework that cannot be deceived by the limitations of any single instrument, any single variable, any single view.

The ocean is proof of concept. The concept is general.
