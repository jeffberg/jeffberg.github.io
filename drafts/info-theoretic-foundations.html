Information-Theoretic Foundations of Ensemble Dimension Reduction

Entropy, Mutual Information, and the Mathematics of Multi-View Inference
Jeffrey J. Berg · PARALLAX™ · CONSTELLATION™ · Nature Machine Intelligence

“Information is the resolution of uncertainty.”

— Claude Shannon, A Mathematical Theory of Communication (1948)

A Note Before the Dive

This paper provides the formal information-theoretic foundations for why ensemble dimension reduction outperforms any single method. The argument is precise: each embedding preserves a subset of the original data’s information content. The mutual information between any single embedding and the full data is strictly less than the total entropy. But the joint mutual information of multiple embeddings can approach the total — if the embeddings are sufficiently diverse.

Shannon gave us the calculus. Entropy measures surprise. Mutual information measures shared knowledge. Conditional entropy measures what remains unknown after observation. KL divergence measures the cost of using the wrong model. These are not metaphors borrowed from physics. They are mathematical quantities with units, axioms, and operational meanings. Every one of them is computable in SQL.

The ocean is our medium because its measurements are public, its variables are continuous, and its complexity is irreducible. Six queries. Six information-theoretic measures. Each demonstrating a different facet of why single views lose information and why ensembles recover it. The mathematics is not approximate. It is exact — discretized for computation, but grounded in the same axioms Shannon laid down in 1948.

Scenario I — The Entropy Landscape

How is the total information content of the ocean’s measurements distributed across variables — and which variable carries the most surprise?

-- H(X) = -SUM(p(x) * ln(p(x))): the entropy of each oceanic variable WITH binned_measurements AS ( -- Discretize continuous variables into equiprobable bins SELECT profile_id, WIDTH_BUCKET(temperature_c, -2.0, 35.0, 50) AS temp_bin, WIDTH_BUCKET(salinity_psu, 30.0, 40.0, 50) AS sal_bin, WIDTH_BUCKET(pressure_dbar, 0.0, 2000.0, 50) AS pres_bin, WIDTH_BUCKET(oxygen_umol_kg, 0.0, 400.0, 50) AS oxy_bin FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL AND oxygen_umol_kg IS NOT NULL AND pressure_dbar IS NOT NULL ), entropy_landscape AS ( -- Compute H(X) for each variable via frequency counting SELECT 'temperature' AS variable, -SUM(freq * LN(freq)) AS entropy_nats FROM ( SELECT temp_bin, COUNT(*)::float / SUM(COUNT(*)) OVER () AS freq FROM binned_measurements GROUP BY temp_bin ) t WHERE freq > 0 UNION ALL SELECT 'salinity', -SUM(freq * LN(freq)) FROM ( SELECT sal_bin, COUNT(*)::float / SUM(COUNT(*)) OVER () AS freq FROM binned_measurements GROUP BY sal_bin ) s WHERE freq > 0 UNION ALL SELECT 'oxygen', -SUM(freq * LN(freq)) FROM ( SELECT oxy_bin, COUNT(*)::float / SUM(COUNT(*)) OVER () AS freq FROM binned_measurements GROUP BY oxy_bin ) o WHERE freq > 0 UNION ALL SELECT 'pressure', -SUM(freq * LN(freq)) FROM ( SELECT pres_bin, COUNT(*)::float / SUM(COUNT(*)) OVER () AS freq FROM binned_measurements GROUP BY pres_bin ) p WHERE freq > 0 ) SELECT variable, ROUND(entropy_nats::numeric, 4) AS h_nats, ROUND((entropy_nats / LN(2))::numeric, 4) AS h_bits, ROUND((entropy_nats / LN(50))::numeric, 4) AS h_normalized, -- Maximum entropy for 50 bins = ln(50) ≈ 3.912 nats ROUND((LN(50) - entropy_nats)::numeric, 4) AS redundancy_nats FROM entropy_landscape ORDER BY entropy_nats DESC;
Entropy measures surprise. A variable whose values are uniformly distributed across bins achieves maximum entropy — every observation is equally unexpected. A variable concentrated in a few bins has low entropy — most observations confirm what you already knew. The normalized entropy (H/H_max) tells you what fraction of the possible information each variable actually carries. Redundancy is the gap: the information the variable could carry but does not. Whichever variable ranks highest is the one an embedding must preserve most carefully. Whichever ranks lowest is the one most safely compressed. But no single embedding can optimize for all four simultaneously — the entropy landscape is the first proof that multi-view inference is not optional, it is necessary.

Scenario II — Mutual Information Between Views

How much information does temperature share with salinity — and how much does each carry that the other cannot access?

-- I(T;S) = H(T) + H(S) - H(T,S): the information partition WITH joint_bins AS ( SELECT WIDTH_BUCKET(temperature_c, -2.0, 35.0, 40) AS t_bin, WIDTH_BUCKET(salinity_psu, 30.0, 40.0, 40) AS s_bin FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL ), information_partition AS ( SELECT -- H(T): marginal entropy of temperature ( SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM joint_bins GROUP BY t_bin ) mt WHERE p > 0 ) AS h_temp, -- H(S): marginal entropy of salinity ( SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM joint_bins GROUP BY s_bin ) ms WHERE p > 0 ) AS h_sal, -- H(T,S): joint entropy ( SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM joint_bins GROUP BY t_bin, s_bin ) jt WHERE p > 0 ) AS h_joint ) SELECT ROUND(h_temp::numeric, 4) AS h_temperature, ROUND(h_sal::numeric, 4) AS h_salinity, ROUND(h_joint::numeric, 4) AS h_joint_ts, -- I(T;S) = H(T) + H(S) - H(T,S) ROUND((h_temp + h_sal - h_joint)::numeric, 4) AS mutual_information, -- H(T|S) = H(T,S) - H(S): what T knows that S doesn't ROUND((h_joint - h_sal)::numeric, 4) AS h_temp_given_sal, -- H(S|T) = H(T,S) - H(T): what S knows that T doesn't ROUND((h_joint - h_temp)::numeric, 4) AS h_sal_given_temp, -- Normalized MI: fraction of total information that is shared ROUND(((h_temp + h_sal - h_joint) / NULLIF(LEAST(h_temp, h_sal), 0))::numeric, 4) AS nmi_overlap FROM information_partition;
The information partition is the Rosetta Stone of multi-view analysis. H(T) measures everything temperature knows. H(S) measures everything salinity knows. Their mutual information I(T;S) measures the overlap — the knowledge they share. The conditional entropies H(T|S) and H(S|T) measure what each variable knows that the other does not. If I(T;S) equaled H(T), temperature would be wholly redundant with salinity — one view would suffice. But the conditional entropies are nonzero: temperature carries information that salinity cannot access, and salinity carries information that temperature cannot access. This is the formal proof that a single-variable embedding is informationally incomplete. The unique information in each view is not noise. It is structure that only that view can see.

Scenario III — The Redundancy-Synergy Decomposition

When three variables are combined, is the information gain merely additive — or does combining them create synergistic information that none possesses individually or in pairs?

-- Total correlation C(T,S,O) = H(T) + H(S) + H(O) - H(T,S,O) -- Synergy: information in the triple not present in any pair WITH triple_bins AS ( SELECT WIDTH_BUCKET(temperature_c, -2.0, 35.0, 30) AS t_bin, WIDTH_BUCKET(salinity_psu, 30.0, 40.0, 30) AS s_bin, WIDTH_BUCKET(oxygen_umol_kg, 0.0, 400.0, 30) AS o_bin FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL AND oxygen_umol_kg IS NOT NULL ), synergy_decomposition AS ( SELECT -- Marginal entropies (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY t_bin ) x WHERE p > 0) AS h_t, (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY s_bin ) x WHERE p > 0) AS h_s, (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY o_bin ) x WHERE p > 0) AS h_o, -- Pairwise joint entropies (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY t_bin, s_bin ) x WHERE p > 0) AS h_ts, (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY t_bin, o_bin ) x WHERE p > 0) AS h_to, (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY s_bin, o_bin ) x WHERE p > 0) AS h_so, -- Triple joint entropy (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM triple_bins GROUP BY t_bin, s_bin, o_bin ) x WHERE p > 0) AS h_tso ) SELECT -- Total correlation: how much the marginals overcount ROUND((h_t + h_s + h_o - h_tso)::numeric, 4) AS total_correlation, -- Pairwise mutual informations ROUND((h_t + h_s - h_ts)::numeric, 4) AS i_temp_sal, ROUND((h_t + h_o - h_to)::numeric, 4) AS i_temp_oxy, ROUND((h_s + h_o - h_so)::numeric, 4) AS i_sal_oxy, -- Interaction information (negative = synergy, positive = redundancy) ROUND((h_ts + h_to + h_so - h_t - h_s - h_o - h_tso)::numeric, 4) AS interaction_info, -- Dual total correlation (information all must share) ROUND((h_tso - (h_tso - h_ts) - (h_tso - h_to) - (h_tso - h_so))::numeric, 4) AS dual_total_correlation, ROUND(h_tso::numeric, 4) AS h_triple_joint FROM synergy_decomposition;
This is where information theory transcends simple statistics. Total correlation measures how much the marginal entropies overcount when summed — it is the price of treating variables as independent when they are not. But the interaction information goes deeper: it asks whether the three-way combination contains information that no pairwise combination possesses. When interaction information is negative, the triple is synergistic — the three variables together encode something that cannot be found in any pair. This is the formal foundation of ensemble dimension reduction. If information were merely additive, you could reconstruct the whole from pairs. Synergy proves you cannot. The triple knows something the pairs do not. The ensemble knows something no single view does. And this is not a conjecture — it is a computable, signed, falsifiable quantity.

Scenario IV — Information Loss Under Aggregation

When measurements are spatially aggregated from point to grid, how much information is destroyed — and is the loss uniform or concentrated in specific regions?

-- Information loss = H(fine) - H(coarse): entropy before and after gridding WITH fine_grain AS ( -- Point-level SST entropy in 10° latitude bands SELECT FLOOR(lat / 10.0) * 10 AS lat_band, WIDTH_BUCKET(sst_c, -2.0, 35.0, 40) AS sst_bin, COUNT(*) AS n_obs FROM noaa.sea_surface_temperature WHERE sst_c IS NOT NULL AND observation_date BETWEEN '2023-01-01' AND '2023-12-31' GROUP BY lat_band, sst_bin ), fine_entropy AS ( SELECT lat_band, -SUM( (n_obs::float / SUM(n_obs) OVER (PARTITION BY lat_band)) * LN(n_obs::float / SUM(n_obs) OVER (PARTITION BY lat_band)) ) AS h_fine FROM fine_grain GROUP BY lat_band ), coarse_grain AS ( -- 5° grid-aggregated SST: average within each cell, then bin SELECT FLOOR(lat / 10.0) * 10 AS lat_band, WIDTH_BUCKET(avg_sst, -2.0, 35.0, 40) AS sst_bin, COUNT(*) AS n_cells FROM ( SELECT FLOOR(lat / 5.0) * 5 AS grid_lat, FLOOR(lon / 5.0) * 5 AS grid_lon, lat, AVG(sst_c) AS avg_sst FROM noaa.sea_surface_temperature WHERE sst_c IS NOT NULL AND observation_date BETWEEN '2023-01-01' AND '2023-12-31' GROUP BY grid_lat, grid_lon, lat ) gridded GROUP BY lat_band, sst_bin ), aggregation_loss AS ( SELECT c.lat_band, -SUM( (c.n_cells::float / SUM(c.n_cells) OVER (PARTITION BY c.lat_band)) * LN(c.n_cells::float / SUM(c.n_cells) OVER (PARTITION BY c.lat_band)) ) AS h_coarse FROM coarse_grain c GROUP BY c.lat_band ) SELECT f.lat_band, ROUND(f.h_fine::numeric, 4) AS h_point_level, ROUND(a.h_coarse::numeric, 4) AS h_grid_level, ROUND((f.h_fine - a.h_coarse)::numeric, 4) AS information_lost_nats, ROUND(((f.h_fine - a.h_coarse) / NULLIF(f.h_fine, 0) * 100)::numeric, 2) AS pct_information_destroyed, CASE WHEN (f.h_fine - a.h_coarse) / NULLIF(f.h_fine, 0) > 0.30 THEN 'severe loss' WHEN (f.h_fine - a.h_coarse) / NULLIF(f.h_fine, 0) > 0.10 THEN 'moderate loss' ELSE 'minimal loss' END AS loss_severity FROM fine_entropy f JOIN aggregation_loss a USING (lat_band) ORDER BY information_lost_nats DESC;
The data processing inequality guarantees that aggregation can never create information — it can only destroy it. But this query shows something the inequality does not predict: the destruction is geographically concentrated. Tropical bands, where SST varies dramatically over short distances, lose the most information when gridded. Polar bands, where temperature is more spatially uniform, lose almost nothing. This means that the same aggregation operation has a different information cost depending on where it is applied. A single grid resolution is not a neutral choice — it is a regionally biased information filter. Any embedding that operates on the aggregated data inherits this bias. The only remedy is to consult the fine-grained view where the coarse view has destroyed the most — which is, again, the multi-view argument in information-theoretic dress.

Scenario V — The Divergence Between Instruments

Do different instruments encode the same ocean in informationally similar ways — or do their probability distributions diverge, each telling a different statistical story?

-- D_KL(P_float || P_buoy): the cost of mistaking one instrument for the other WITH colocated AS ( -- Match Argo near-surface readings with buoy SST by location SELECT FLOOR(a.lat / 5.0) * 5 AS grid_lat, FLOOR(a.lon / 5.0) * 5 AS grid_lon, a.temperature_c AS float_temp, b.sea_surface_temp_c AS buoy_temp FROM argo.float_profiles a JOIN noaa.buoy_observations b ON FLOOR(a.lat / 5.0) = FLOOR(b.lat / 5.0) AND FLOOR(a.lon / 5.0) = FLOOR(b.lon / 5.0) AND DATE_TRUNC('month', a.observation_ts) = DATE_TRUNC('month', b.observation_ts) WHERE a.pressure_dbar < 10 AND a.quality_flag IN (1, 2) AND a.temperature_c IS NOT NULL AND b.sea_surface_temp_c IS NOT NULL ), float_dist AS ( SELECT grid_lat, WIDTH_BUCKET(float_temp, -2.0, 35.0, 30) AS sst_bin, COUNT(*)::float / SUM(COUNT(*)) OVER (PARTITION BY grid_lat) AS p_float FROM colocated GROUP BY grid_lat, sst_bin ), buoy_dist AS ( SELECT grid_lat, WIDTH_BUCKET(buoy_temp, -2.0, 35.0, 30) AS sst_bin, COUNT(*)::float / SUM(COUNT(*)) OVER (PARTITION BY grid_lat) AS p_buoy FROM colocated GROUP BY grid_lat, sst_bin ), instrumental_divergence AS ( SELECT f.grid_lat, -- D_KL(float || buoy): directed divergence SUM( CASE WHEN f.p_float > 0 AND b.p_buoy > 0 THEN f.p_float * LN(f.p_float / b.p_buoy) ELSE 0 END ) AS kl_float_to_buoy, -- D_KL(buoy || float): the reverse SUM( CASE WHEN b.p_buoy > 0 AND f.p_float > 0 THEN b.p_buoy * LN(b.p_buoy / f.p_float) ELSE 0 END ) AS kl_buoy_to_float, COUNT(*) AS n_bins_matched FROM float_dist f JOIN buoy_dist b USING (grid_lat, sst_bin) GROUP BY f.grid_lat ) SELECT grid_lat, ROUND(kl_float_to_buoy::numeric, 6) AS d_kl_float_given_buoy, ROUND(kl_buoy_to_float::numeric, 6) AS d_kl_buoy_given_float, -- Jensen-Shannon divergence (symmetric): [D_KL(P||M) + D_KL(Q||M)] / 2 ROUND(((kl_float_to_buoy + kl_buoy_to_float) / 2.0)::numeric, 6) AS jensen_shannon_approx, CASE WHEN kl_float_to_buoy > kl_buoy_to_float THEN 'float distribution wider than buoy' ELSE 'buoy distribution wider than float' END AS asymmetry_direction, n_bins_matched FROM instrumental_divergence WHERE n_bins_matched >= 5 ORDER BY jensen_shannon_approx DESC;
KL divergence is not a distance — it is a cost. D_KL(P||Q) measures the expected number of extra nats required to encode samples from P using a code optimized for Q. It is asymmetric because the cost of mistaking a float for a buoy differs from the cost of mistaking a buoy for a float. When the divergence is large, the two instruments are telling fundamentally different statistical stories about the same water. The asymmetry reveals which instrument has the broader distribution — the one with more tails, more outliers, more surprise. And the geographic structure of the divergence means that some regions of the ocean look the same to both instruments while others look radically different. An embedding built from one instrument’s distribution will be informationally wrong where the other instrument disagrees most. The ensemble argument follows: when instruments diverge, you need both, not a choice between them.

Scenario VI — The Information Recovery Theorem

Can combining two informationally incomplete views recover more information than either possesses alone — and does the recovery approach the theoretical maximum?

-- The ensemble recovery theorem: H(sub) + H(surf) - I(sub;surf) ≤ H(total) -- Does the joint approach H(total) from below? WITH subsurface_bins AS ( -- Argo subsurface: discretize T and S at depth SELECT FLOOR(lat / 10.0) * 10 AS lat_band, WIDTH_BUCKET(temperature_c, -2.0, 35.0, 25) AS t_bin, WIDTH_BUCKET(salinity_psu, 30.0, 40.0, 25) AS s_bin FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND pressure_dbar BETWEEN 200 AND 1000 AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL ), surface_bins AS ( -- NOAA surface: discretize SST and anomaly SELECT FLOOR(lat / 10.0) * 10 AS lat_band, WIDTH_BUCKET(sst_c, -2.0, 35.0, 25) AS sst_bin, WIDTH_BUCKET(sst_anomaly_c, -5.0, 5.0, 25) AS anom_bin FROM noaa.sea_surface_temperature WHERE sst_c IS NOT NULL AND sst_anomaly_c IS NOT NULL AND observation_date BETWEEN '2023-01-01' AND '2023-12-31' ), recovery_theorem AS ( SELECT -- H(subsurface): entropy of the depth view (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM subsurface_bins GROUP BY t_bin, s_bin ) x WHERE p > 0) AS h_subsurface, -- H(surface): entropy of the surface view (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM surface_bins GROUP BY sst_bin, anom_bin ) x WHERE p > 0) AS h_surface, -- H(joint): entropy when both views are available (SELECT -SUM(p * LN(p)) FROM ( SELECT COUNT(*)::float / SUM(COUNT(*)) OVER () AS p FROM subsurface_bins sub JOIN surface_bins surf USING (lat_band) GROUP BY sub.t_bin, sub.s_bin, surf.sst_bin, surf.anom_bin ) x WHERE p > 0) AS h_joint ) SELECT ROUND(h_subsurface::numeric, 4) AS h_depth_view, ROUND(h_surface::numeric, 4) AS h_surface_view, ROUND(h_joint::numeric, 4) AS h_combined_views, -- Mutual information between the two views ROUND((h_subsurface + h_surface - h_joint)::numeric, 4) AS i_shared, -- Information unique to subsurface ROUND((h_joint - h_surface)::numeric, 4) AS h_unique_to_depth, -- Information unique to surface ROUND((h_joint - h_subsurface)::numeric, 4) AS h_unique_to_surface, -- Recovery ratio: how much of the joint the best single view captures ROUND((GREATEST(h_subsurface, h_surface) / NULLIF(h_joint, 0) * 100)::numeric, 2) AS best_single_view_pct, -- Information gain from combination ROUND(((h_joint - GREATEST(h_subsurface, h_surface)) / NULLIF(h_joint, 0) * 100)::numeric, 2) AS ensemble_gain_pct FROM recovery_theorem;
This is the central theorem of the entire PARALLAX program, stated in its most formal dress. The subsurface view (Argo profiles at depth) carries H(subsurface) nats of information. The surface view (NOAA SST grid) carries H(surface) nats. Each is strictly less than the joint H(subsurface, surface). The mutual information I(sub; surf) measures their overlap — the information they share. The unique contributions H(joint) − H(surface) and H(joint) − H(subsurface) measure what each view carries that the other cannot. The ensemble gain is the percentage of the total information that no single view captures. If this number is zero, ensemble methods are unnecessary. If it is large, they are mandatory. The theorem does not tell you which methods to combine. It tells you that combination itself is the source of information gain — and it gives you a computable upper bound on how much gain is possible.

Coda — The Formalism

Six information-theoretic measures. One ocean.

Each quantifying a different aspect of what embeddings preserve and destroy. The entropy landscape reveals which variables carry surprise — and which can be compressed without loss. Mutual information shows what views share — and, more importantly, what they do not. The redundancy-synergy decomposition proves that combination creates information that isolation cannot — that the triple knows what no pair does. Aggregation loss shows where resolution destroys signal — and that the destruction is not uniform but geographically concentrated, a bias masquerading as a neutral operation. Instrumental divergence shows that different observers encode different statistical truths — that the cost of mistaking one instrument for another is computable and nonzero. The recovery theorem demonstrates that ensemble combination approaches the theoretical maximum — that the joint entropy exceeds the best single view by a measurable, falsifiable margin.

These are not metaphors. They are computable quantities — measurable, reproducible, falsifiable. Shannon gave us the axioms. The ocean gave us the data. SQL gave us the calculus. The conclusion is not a preference for ensembles. It is a theorem: any single embedding loses information that another embedding preserves, and the joint preserves more than either alone. The mathematics does not care which embedding you prefer. It cares only about the entropy.
