The Impossibility of Single-View Intelligence

Why One Projection Cannot Recover What Many Projections Preserve
Jeffrey J. Berg · PARALLAX™ · CONSTELLATION™

“A surface is not exhausted by any single chart. It requires an atlas.”

— Bernhard Riemann, Habilitationsschrift (1854)

A Note Before the Dive

Gauss proved in 1827 that intrinsic curvature is invariant under isometry — no projection of a curved surface to a plane preserves both distances and angles. The Theorema Egregium is not a limitation of technique. It is a property of geometry itself. And yet the field of dimension reduction has spent fifty years debating “which projection is best” while ignoring the theorem that proves the question is malformed.

This paper formalizes the impossibility: no single low-dimensional embedding can preserve all structure. Every projection destroys something. The only question worth asking is what each method loses — and whether the losses can be recovered by combining multiple views that sacrifice different things.

The ocean is our proving ground. Not because it is simple, but because its complexity is measurable, its dimensions are known, and its structure resists every attempt at single-view summary. Six queries. One theorem. The impossibility is not a problem to be solved. It is a constraint to be respected — and leveraged.

Scenario I — The Distance-Angle Tradeoff

Can a single two-dimensional summary preserve both the pairwise distances and the angular relationships among ocean profiles — or does preserving one necessarily sacrifice the other?

-- The distance portrait and the angle portrait of the same profiles WITH profile_vectors AS ( SELECT profile_id, temperature_c, salinity_psu, pressure_dbar, COALESCE(oxygen_umol_kg, 0) AS oxygen_filled FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL LIMIT 2000 ), distance_portrait AS ( -- Euclidean distance: preserves magnitude separation SELECT a.profile_id AS id_a, b.profile_id AS id_b, SQRT( POWER(a.temperature_c - b.temperature_c, 2) + POWER(a.salinity_psu - b.salinity_psu, 2) + POWER(a.pressure_dbar - b.pressure_dbar, 2) + POWER(a.oxygen_filled - b.oxygen_filled, 2) ) AS euclidean_dist FROM profile_vectors a CROSS JOIN profile_vectors b WHERE a.profile_id < b.profile_id ), angle_portrait AS ( -- Cosine similarity: preserves directional alignment SELECT a.profile_id AS id_a, b.profile_id AS id_b, (a.temperature_c * b.temperature_c + a.salinity_psu * b.salinity_psu + a.pressure_dbar * b.pressure_dbar + a.oxygen_filled * b.oxygen_filled) / NULLIF( SQRT(POWER(a.temperature_c,2) + POWER(a.salinity_psu,2) + POWER(a.pressure_dbar,2) + POWER(a.oxygen_filled,2)) * SQRT(POWER(b.temperature_c,2) + POWER(b.salinity_psu,2) + POWER(b.pressure_dbar,2) + POWER(b.oxygen_filled,2)), 0 ) AS cosine_sim FROM profile_vectors a CROSS JOIN profile_vectors b WHERE a.profile_id < b.profile_id ) -- Measure the correlation between the two portraits SELECT ROUND(CORR(d.euclidean_dist, a.cosine_sim)::numeric, 4) AS dist_angle_correlation, ROUND(AVG(d.euclidean_dist)::numeric, 4) AS mean_distance, ROUND(AVG(a.cosine_sim)::numeric, 4) AS mean_cosine_sim, COUNT(*) AS n_pairs FROM distance_portrait d JOIN angle_portrait a ON d.id_a = a.id_a AND d.id_b = a.id_b;
If the correlation were perfect — if knowing distances told you everything about angles — then a single embedding could serve both masters. But it cannot. Profiles that are far apart in magnitude may point in similar directions; profiles that are close in Euclidean space may diverge angularly. This is not a bug in the metrics. It is Gauss’s theorem made computational: the distance chart and the angle chart are two maps of the same territory, and no single map is both. The tradeoff is not a failure of method. It is a property of projection itself.

Scenario II — The Variance Partition

How much of the ocean’s total variance lives in the first two principal directions — and what does the remainder contain that the summary cannot?

-- Partition total variance into what PCA keeps and what it discards WITH standardized_profiles AS ( SELECT profile_id, (temperature_c - AVG(temperature_c) OVER ()) / NULLIF(STDDEV(temperature_c) OVER (), 0) AS z_temp, (salinity_psu - AVG(salinity_psu) OVER ()) / NULLIF(STDDEV(salinity_psu) OVER (), 0) AS z_sal, (pressure_dbar - AVG(pressure_dbar) OVER ()) / NULLIF(STDDEV(pressure_dbar) OVER (), 0) AS z_pres, (COALESCE(oxygen_umol_kg, 0) - AVG(COALESCE(oxygen_umol_kg, 0)) OVER ()) / NULLIF(STDDEV(COALESCE(oxygen_umol_kg, 0)) OVER (), 0) AS z_oxy FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL ), variance_partition AS ( -- Total variance = sum of variances across all 4 standardized dims (= 4) -- Max-variance 2D projection captures the two largest eigenvalue directions -- Approximate via pairwise covariance structure SELECT COUNT(*) AS n_profiles, ROUND((POWER(CORR(z_temp, z_sal), 2) + POWER(CORR(z_temp, z_pres), 2) + POWER(CORR(z_temp, z_oxy), 2) + POWER(CORR(z_sal, z_pres), 2) + POWER(CORR(z_sal, z_oxy), 2) + POWER(CORR(z_pres, z_oxy), 2))::numeric, 4) AS sum_squared_corr, 4.0 AS total_variance FROM standardized_profiles ), residual_structure AS ( -- Test whether the residual is random or structured: -- if oxygen correlates with salinity after removing temp+pressure, -- the residual carries signal, not noise SELECT ROUND(CORR(z_oxy, z_sal)::numeric, 4) AS oxy_sal_corr, ROUND(CORR(z_oxy, z_sal - REGR_SLOPE(z_sal, z_temp) * z_temp )::numeric, 4) AS oxy_sal_partial FROM standardized_profiles ) SELECT vp.n_profiles, vp.total_variance, vp.sum_squared_corr AS redundancy_index, ROUND((vp.total_variance - vp.sum_squared_corr)::numeric, 4) AS estimated_residual, rs.oxy_sal_corr, rs.oxy_sal_partial AS partial_after_temp, CASE WHEN ABS(rs.oxy_sal_partial) > 0.10 THEN 'residual is structured' ELSE 'residual is noise' END AS residual_diagnosis FROM variance_partition vp CROSS JOIN residual_structure rs;
The two-dimensional summary — the one that captures “most of the variance” — is the view the field treats as sufficient. But sufficiency requires that the discarded remainder be noise. This query tests that assumption directly. When the partial correlation between oxygen and salinity survives the removal of temperature and pressure, the residual is not noise. It is signal that the first two components were structurally incapable of representing. The variance partition is not a budget where leftovers are scraps. It is a triage where the discarded dimensions may contain exactly the structure that matters most.

Scenario III — The Neighborhood Contradiction

Do the same profiles that are neighbors in temperature space remain neighbors in salinity space — or does each variable impose a different topology on the same set of points?

-- Two topologies on the same set of profiles WITH ranked_profiles AS ( SELECT profile_id, float_id, temperature_c, salinity_psu, lat, lon FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL AND pressure_dbar BETWEEN 50 AND 150 LIMIT 5000 ), temp_neighbors AS ( -- For each profile, find its closest 10 neighbors by temperature SELECT a.profile_id AS anchor_id, b.profile_id AS neighbor_id, ABS(a.temperature_c - b.temperature_c) AS temp_dist, ROW_NUMBER() OVER ( PARTITION BY a.profile_id ORDER BY ABS(a.temperature_c - b.temperature_c) ASC ) AS temp_rank FROM ranked_profiles a JOIN ranked_profiles b ON a.profile_id != b.profile_id ), sal_neighbors AS ( -- Same profiles, same count, ranked by salinity SELECT a.profile_id AS anchor_id, b.profile_id AS neighbor_id, ABS(a.salinity_psu - b.salinity_psu) AS sal_dist, ROW_NUMBER() OVER ( PARTITION BY a.profile_id ORDER BY ABS(a.salinity_psu - b.salinity_psu) ASC ) AS sal_rank FROM ranked_profiles a JOIN ranked_profiles b ON a.profile_id != b.profile_id ) -- Measure neighborhood overlap: what fraction of temp-neighbors -- are also sal-neighbors? SELECT ROUND(AVG(overlap_count)::numeric, 2) AS mean_overlap, ROUND(STDDEV(overlap_count)::numeric, 2) AS overlap_stddev, ROUND(AVG(overlap_count / 10.0)::numeric, 4) AS jaccard_at_k10, COUNT(DISTINCT anchor_id) AS n_anchors FROM ( SELECT t.anchor_id, COUNT(s.neighbor_id) AS overlap_count FROM temp_neighbors t LEFT JOIN sal_neighbors s ON t.anchor_id = s.anchor_id AND t.neighbor_id = s.neighbor_id AND s.sal_rank <= 10 WHERE t.temp_rank <= 10 GROUP BY t.anchor_id ) topology_clash;
If temperature and salinity imposed the same topology — if knowing who is close in one told you who is close in the other — then choosing either variable as a basis for clustering would be harmless. But they do not. A Jaccard overlap well below 1.0 means that the neighborhoods defined by temperature are substantially different from those defined by salinity. The same profiles, the same ocean, two irreconcilable definitions of “nearby.” A single-variable view does not merely simplify the topology. It replaces it with a different one — and the replacement is silent, invisible to anyone who never computes the second view.

Scenario IV — The Temporal Incompleteness

Does a spatial snapshot of the ocean contain the same information as a temporal trajectory through the same region — or does compressing time destroy structure that space preserves?

-- Space vs. time: two fundamentally different compressions WITH spatial_snapshot AS ( -- Cross-section: all locations on a single date SELECT grid_id, lat, lon, sst_c, sst_anomaly_c FROM noaa.sea_surface_temperature WHERE observation_date = '2023-07-15' AND sst_c IS NOT NULL ), temporal_trajectory AS ( -- Time series: one location across many dates SELECT observation_date, sst_c, sst_anomaly_c, sst_c - LAG(sst_c) OVER ( ORDER BY observation_date ) AS daily_delta, STDDEV(sst_c) OVER ( ORDER BY observation_date ROWS BETWEEN 30 PRECEDING AND CURRENT ROW ) AS rolling_volatility FROM noaa.sea_surface_temperature WHERE lat BETWEEN 30 AND 32 AND lon BETWEEN -80 AND -78 AND sst_c IS NOT NULL ORDER BY observation_date ), cross_information AS ( -- What spatial variance tells you vs. what temporal variance tells you SELECT 'spatial' AS view_type, ROUND(STDDEV(sst_c)::numeric, 4) AS sst_spread, ROUND(STDDEV(sst_anomaly_c)::numeric, 4) AS anomaly_spread, COUNT(*) AS n_obs FROM spatial_snapshot UNION ALL SELECT 'temporal' AS view_type, ROUND(STDDEV(sst_c)::numeric, 4) AS sst_spread, ROUND(STDDEV(sst_anomaly_c)::numeric, 4) AS anomaly_spread, COUNT(*) AS n_obs FROM temporal_trajectory ) SELECT view_type, sst_spread, anomaly_spread, n_obs, ROUND((anomaly_spread / NULLIF(sst_spread, 0))::numeric, 4) AS anomaly_to_total_ratio FROM cross_information ORDER BY view_type;
Spatial variance and temporal variance are not interchangeable summaries of the same phenomenon. The spatial snapshot captures the geography of the ocean on a single day — equator warm, poles cold, currents carving boundaries. The temporal trajectory captures the memory of one place — seasons, El Niño cycles, regime shifts. Each is a projection onto a different axis, and the projections are not redundant. When they produce different anomaly-to-total ratios, it means the signal structure itself changes depending on which axis you compress. Time and space are not two descriptions of one truth. They are two truths about one ocean.

Scenario V — The Depth Collapse

When we average across depth to produce a single surface value, what vertical structure vanishes — and does the lost structure carry signal or noise?

-- What depth-averaging destroys and whether it matters WITH depth_resolved AS ( SELECT float_id, cycle_number, ROUND(lat::numeric, 0) AS lat_band, ROUND(lon::numeric, 0) AS lon_band, pressure_dbar, temperature_c, salinity_psu FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL ), column_statistics AS ( -- Per water column: mean, vertical variance, vertical range SELECT float_id, cycle_number, lat_band, lon_band, AVG(temperature_c) AS col_mean_temp, STDDEV(temperature_c) AS col_temp_spread, MAX(temperature_c) - MIN(temperature_c) AS col_temp_range, AVG(salinity_psu) AS col_mean_sal, STDDEV(salinity_psu) AS col_sal_spread, COUNT(*) AS n_depths FROM depth_resolved GROUP BY float_id, cycle_number, lat_band, lon_band HAVING COUNT(*) >= 5 ), signal_test AS ( -- Does vertical structure predict horizontal location? -- If yes, the collapsed dimension carried spatial signal SELECT ROUND(CORR(col_temp_spread, lat_band)::numeric, 4) AS vert_var_vs_lat, ROUND(CORR(col_temp_range, lat_band)::numeric, 4) AS vert_range_vs_lat, ROUND(CORR(col_sal_spread, lon_band)::numeric, 4) AS sal_spread_vs_lon, ROUND(AVG(col_temp_spread)::numeric, 4) AS mean_vert_spread, ROUND(STDDEV(col_temp_spread)::numeric, 4) AS spread_of_spread, COUNT(*) AS n_columns FROM column_statistics ) SELECT n_columns, mean_vert_spread, spread_of_spread, vert_var_vs_lat AS vertical_predicts_latitude, vert_range_vs_lat AS range_predicts_latitude, sal_spread_vs_lon AS sal_spread_predicts_longitude, CASE WHEN ABS(vert_var_vs_lat) > 0.15 OR ABS(sal_spread_vs_lon) > 0.15 THEN 'depth collapse destroys signal' ELSE 'depth collapse is benign' END AS collapse_verdict FROM signal_test;
Depth-averaging is the most common projection in oceanography and the most invisible. Every surface map is a depth collapse — an implicit claim that vertical variation is either uniform or irrelevant. This query tests that claim by asking whether the amount of vertical spread in a water column predicts where that column is located. If it does, then depth-averaging has not merely smoothed the data. It has destroyed a dimension that carried geographic information. The tropics stratify sharply; the poles mix deeply. That gradient — the vertical signature of latitude — vanishes completely in a depth-averaged view. The collapse was never neutral. It was a lossy projection disguised as a convenience.

Scenario VI — The Multi-View Recovery

Can we recover information that any single view destroys — by combining two views that lose different things?

-- The atlas theorem: two incomplete views recover what neither has alone WITH subsurface_view AS ( -- Argo profiles: rich vertical structure, sparse horizontal coverage SELECT ROUND(lat::numeric, 0) AS lat_band, ROUND(lon::numeric, 0) AS lon_band, AVG(temperature_c) AS subsurface_mean_temp, STDDEV(temperature_c) AS subsurface_temp_var, AVG(salinity_psu) AS subsurface_mean_sal, COUNT(DISTINCT profile_id) AS n_profiles FROM argo.float_profiles WHERE quality_flag IN (1, 2) AND temperature_c IS NOT NULL AND salinity_psu IS NOT NULL GROUP BY lat_band, lon_band HAVING COUNT(DISTINCT profile_id) >= 3 ), surface_view AS ( -- SST grid: dense horizontal coverage, no depth information SELECT ROUND(lat::numeric, 0) AS lat_band, ROUND(lon::numeric, 0) AS lon_band, AVG(sst_c) AS surface_mean_temp, STDDEV(sst_anomaly_c) AS surface_anomaly_var, COUNT(*) AS n_gridcells FROM noaa.sea_surface_temperature WHERE sst_c IS NOT NULL AND observation_date BETWEEN '2023-01-01' AND '2023-12-31' GROUP BY lat_band, lon_band ), combined_atlas AS ( -- Join the two views: what does the combination reveal? SELECT sub.lat_band, sub.lon_band, sub.subsurface_mean_temp, sub.subsurface_temp_var, sub.subsurface_mean_sal, surf.surface_mean_temp, surf.surface_anomaly_var, -- The gap between surface and subsurface is new information sub.subsurface_mean_temp - surf.surface_mean_temp AS thermal_gradient, sub.n_profiles, surf.n_gridcells FROM subsurface_view sub JOIN surface_view surf USING (lat_band, lon_band) ) SELECT -- Information in each view alone vs. the combination ROUND(CORR(surface_mean_temp, subsurface_mean_sal)::numeric, 4) AS surface_predicts_sal, ROUND(CORR(thermal_gradient, subsurface_temp_var)::numeric, 4) AS gradient_predicts_depth_var, ROUND(CORR(surface_anomaly_var, subsurface_temp_var)::numeric, 4) AS surface_var_vs_depth_var, ROUND(STDDEV(thermal_gradient)::numeric, 4) AS gradient_spread, COUNT(*) AS n_cells_both_views, CASE WHEN ABS(CORR(thermal_gradient, subsurface_temp_var)) > ABS(CORR(surface_mean_temp, subsurface_temp_var)) THEN 'combination exceeds either view' ELSE 'single view suffices' END AS atlas_verdict FROM combined_atlas;
This is the turning point. Five scenarios demonstrated impossibility — the many ways a single projection fails. This scenario demonstrates recovery. The surface grid knows the ocean’s horizontal face but nothing of its vertical soul. The Argo floats know the vertical architecture but visit only scattered columns. Neither view is sufficient. But their combination — the thermal gradient between surface and subsurface, the correlation between surface anomaly variance and depth-resolved variance — produces information that exists in neither source alone. The gradient is an emergent variable: it requires two atlases laid on top of each other. This is not a trick of data fusion. It is the atlas theorem in action. What one chart loses, another preserves. What no single chart can show, the atlas can.

Coda — The Atlas Theorem

Six demonstrations. One theorem.

Each query shows a different face of the same impossibility. The distance view and the angle view cannot agree — preserving one distorts the other, and no single embedding serves both. The variance summary discards structured residuals that carry signal the first two components were never built to see. Temperature neighborhoods and salinity neighborhoods contradict — the same points, the same ocean, two irreconcilable definitions of proximity. Time and space encode different truths about the same phenomenon, and compressing one axis destroys structure the other preserves. Depth collapses not noise but signal — the vertical signature of latitude, erased by an averaging operation disguised as simplification.

But — crucially — multiple incomplete views, combined, recover what no single view preserves. The thermal gradient between surface and subsurface is a variable that exists in neither dataset alone. It emerges only at the seam where two lossy projections overlap. This is not a feature of the ocean. It is a feature of projection itself. Gauss proved it for surfaces. Riemann generalized it for manifolds. And every analyst who has ever chosen a single method for a complex system has collided with it, whether they recognized the collision or not.

The question was never which projection is best. The question was always which projections, taken together, form a sufficient atlas. The impossibility is not the enemy. It is the design constraint. And the path through it is not a better single view but a disciplined plurality of incomplete ones.

“The ocean was simply patient enough to sit for its many portraits.”
